# Nova View in Home Assistant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Nova view on both Home Assistant dashboards that shows Nova's state and works as a controller: mute, Stop, Speak, volumes, timers, next alarm, what Nova is playing with its controls, and an Ask Nova box that sends a typed request as if it had been said.

**Architecture:** The view is first built from the entities the Pi's existing MQTT device already has (Task 1, ha-dashboard only). Nova's `NovaDevice` then gains optional music entities, read on a slow thread of their own because Spotify's `now_playing` is a network call (Task 2), wired to the satellite's session (Task 3), and an Ask Nova text entity (Task 4) whose text the session answers as a typed turn: no microphone, the same conversation and guards, the reply spoken (Task 5). Home Assistant wraps the music entities in a `universal` media player, and the view gains Music and Ask Nova (Task 6).

**Tech Stack:** Python 3 (Nova, existing packages only, paho-mqtt already used), pytest on the Pi; Home Assistant MQTT discovery, `universal` media player, storage-mode dashboards with bubble-card, navbar-card and card-mod.

**Spec:** `docs/superpowers/specs/2026-11-18-nova-view-design.md`

## Global Constraints

- Decision 0005 holds: nothing said to Nova and none of its answers is published. The only typed text on MQTT is on the command topic `{base}/ask/set`; the Ask state topic `{base}/ask` only ever carries the fixed placeholder `-` (retained; an empty retained payload deletes the message at the broker, so HA would never read it after a restart), which the text entity's `value_template` `{{ '' }}` turns into an empty state. Nova's replies are spoken, never published.
- Typed text is logged only as heard text is: with `extra=TRANSCRIPT`, so the transcripts setting decides. No other log line carries it.
- A typed request goes through `Conversation.handle` exactly as transcribed speech does; no new path around its guards.
- Every new `DeviceControls` field defaults to `None`, and an entity is announced only when its control is set, so existing constructions and tests are unchanged.
- The state thread (`PUBLISH_EVERY = 1`) never calls `now_playing`, `cover` or `playlists`. Music is read every `MUSIC_EVERY = 5` seconds on its own thread; playlists every `PLAYLISTS_EVERY = 600` seconds and at each announce; the cover only when the cover id changes.
- New entity ids, through `default_entity_id` built from the device name's slug (`_slug(self.name)`, "nova" for the Pi): `sensor.nova_playing`, `image.nova_playing_cover`, `button.nova_play_pause`, `button.nova_next_track`, `button.nova_previous_track`, `select.nova_playlist`, `text.nova_ask`. Not `nova_music_*`: that glob is the Music device's recorder exclusion.
- Typed-turn constants in `session.py`: `TYPED_ANSWER_WAIT = 60` (seconds to wait for a typed answer to a question), `ASK_MOST = 255` (characters kept of a typed request; the text entity's max is the same).
- Navbar: a Nova button (`mdi:account-voice`) after AI on both bars; on the phone the view sits after AI too, so swipes follow the bar. Desktop: Homelab, AI, Nova, Devices, Home, Music, Planner. Phone: Homelab, AI, Nova, Devices, Home, Music, Planner.

## Review Focus

1. **A typed request arrives while Nova is mid-turn by voice** (not in a follow-up listen): it waits and is answered after, never said over the current reply and never taken by `_say` as a wake word heard over it (`_say` reads `satellite.wakes`; typed requests use their own queue). Test in Task 5.
2. **Nothing is playing, or the player is Spotify with no login:** `now_playing` returns `None`; `sensor.nova_playing` is `idle` with empty attributes, the cover is cleared, Play/pause starts the liked songs as "Hey Nova, play" does. Tests in Tasks 2 and 3.
3. **The satellite goes while a typed answer is awaited:** the wait ends without speaking or raising, and the session closes as usual. Test in Task 5.
4. **A playlist chosen in HA that Nova no longer has** (renamed since the options were sent): not one of the announced options, so nothing is played; one that is still offered goes to `play_playlist`, which says itself if it is missing. Test in Task 2.
5. **A retained message on `{base}/ask/set`** (left on the broker by hand or a bad automation): ignored, as every retained command already is, so Nova never answers it on each reconnect. Test in Task 4.

### Task 5: Typed turns in the session, and decision 0025

**Files:**
- Modify: `voice_assistant/session.py` (`__init__`, `run`, `_answer`, `_handle_interaction`, `_device_controls`; new `ask`, `_handle_typed`, `_reply_to`, `_wait_for_typed_answer`)

**Interfaces:**
- Consumes: Task 4's `DeviceControls.ask`.
- Produces: `Session.ask(text: str) -> None` (thread-safe, returns at once); `Session._reply_to(text: str, follow_up: bool, timeline: Timeline) -> Tuple[Optional[Dict], bool]`, the shared tail of a turn after the words are known (show "You: ...", `conversation.handle`, sounds, shown line, `_say(..., listen=True)`), returning the wake heard over the reply and whether Nova asked a question.

Behaviour (the spec's Decided section, made exact):
- `ask` trims the text to `ASK_MOST` characters and drops it if blank. If a spoken follow-up listen is open, the text becomes that answer: the listen is ended with `satellite.stop_listening(feed)` and the text is used instead of the transcription, which is cancelled. If a typed answer is awaited, the text is that answer. Otherwise it joins `self._typed`, a `queue.Queue` of its own.
- `run` answers a typed request when `satellite.wakes` is empty at its `WAKE_CHECK` timeout, as `self._converse({"typed": text, "talked_over": False, "feed": None})`; a wake word always goes first.
- A typed turn plays no listening sound, sends no `listen`, starts as `activity = "thinking"`, ignores mute, and logs its text only as heard text is.
- When a reply to a typed turn asks a question, the microphone stays shut and Nova waits up to `TYPED_ANSWER_WAIT` seconds for a typed answer, handled with `follow_up=True`. With no answer, or once the satellite has gone, the turn ends silently.
- A question asked in reply to speech is listened for as now; a typed answer arriving during that listen counts, as above.
