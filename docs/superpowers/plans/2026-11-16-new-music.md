# New Music Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SoulSync makes and downloads Spotify-style playlists every night and week, Nova follows his top artists on SoulSync's watchlist each month, and Nova answers "find me something new" and "what's new this week?".

**Architecture:** A one-off, idempotent setup script in the `homelab` repo configures SoulSync's personalised playlists and two pipeline automations over its API. Nova gains a monthly `FollowWatcher` (top artists from `Listening`'s 12-month snapshot onto SoulSync's watchlist), a `newest_albums` read on Navidrome, and two Claude tools. Everything else (picking, downloading, playlists in Navidrome) is SoulSync's.

**Tech Stack:** Python 3 (Nova on the brain, CT 107; stdlib-only script for the setup), requests, pytest on the Pi, stdlib unittest for the script.

**Spec:** `docs/superpowers/specs/2026-11-16-new-music-design.md` (read it first, including "Answers from the builder check").

## Review Focus

1. A top artist SoulSync's watchlist resolves to a different artist (ambiguous ids): the add is undone and logged by count, never left in (Task 1 `test_wrong_artist_is_removed`).
2. SoulSync down or the stats not read yet on the 1st: following is tried again at the next hourly look that month, and never twice once done (Task 1 `test_retries_until_done`, `test_once_a_month`).
3. An artist already on the watchlist (by name, case-insensitive, or id): left alone, not re-added (Task 1 `test_already_watched_left_alone`).
4. "Find me something new" when the playlist doesn't exist yet in Navidrome (before the first Monday run) or the player is Spotify: a plain sentence saying so (Task 2 `test_new_music_playlist_missing`).
5. The setup script run twice, or against a SoulSync where the playlists or automations already exist: no duplicates, no changes on the second run (Task 3 `test_second_run_changes_nothing`).

### Task 1: Following his top artists

**Files:**

- Test: `tests/test_following.py`, additions to `tests/test_soulsync.py`, `tests/test_settings_page.py`, `tests/test_config.py`, `tests/test_brain.py`

**Interfaces:**
- Consumes: `Listening.require()` and its `Snapshot.windows["12m"]["top_artists"]` (`id`, `name`, `play_count`).
- Produces:
  - `SoulSync.watched_artists() -> List[Dict]` (`GET /api/watchlist/artists`; each with at least the name and the ids SoulSync gives).
  - `SoulSync.follow(artist: Dict) -> Optional[Dict]`: adds one artist through whichever request Step 1 shows resolves a stats `id` to the right artist; returns the new watchlist row or None.
  - `SoulSync.unfollow(row: Dict) -> None` (`POST /api/watchlist/remove`).
  - `config.yaml` `new_music:` `follow_top_artists: 25` (0 switches following off) and `playlist: "Discovery Shuffle"` (Task 2 reads it), commented.
  - `EDITABLE`: `("new_music", "follow_top_artists", "How many of your top artists to follow for new releases (0 for none)", "now")`, `("new_music", "playlist", "Playlist for 'find me something new'", "now")`; limits: whole number 0 to 50; text.
  - `class FollowWatcher(listening, soulsync_factory: Callable[[], Optional[SoulSync]], store_path: str, settings: Callable[[], Dict], clock=time.time)`: daemon thread `following`, looks at start and hourly (`LOOK_EVERY = 3600`). Once per calendar month, after 03:00 local on any day of it: takes the top N of the 12-month window, skips those already watched (case-insensitive name or any matching id), follows the rest, checks each new row's name matches (normalised as `navidrome.normalise`), unfollows any that don't, and records the month as done in a small JSON file (`following.json` in the data folder, saved atomically). Logs counts only. `SoulSync` unavailable, `ListeningUnavailable` or N = 0: nothing recorded, tried again next look (N = 0 records nothing and does nothing).
