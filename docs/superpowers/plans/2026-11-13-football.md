# Football Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nova answers football questions about any team or competition from Home Assistant, follows and unfollows teams by voice and on the settings page, and announces the followed teams' matches: starting soon, goals, half time, the second half and full time.

**Architecture:** A new `football.py` on the brain reads `sensor.football_teams` for the followed teams and asks `shell_command.football_ask` for anything else, turning both into text Claude answers from through one tool, `get_football`. A second tool, `follow_team`, and the settings page write Home Assistant's teams box. A watcher in `football_watch.py` reads the sensor every 30 seconds, works out what has happened in each followed team's match from what it last saw, and says it on the default satellite in fixed sentences, with no Claude.

**Tech Stack:** Python 3.13 on the brain, requests, pytest on the Pi, the settings page's plain JavaScript (checked with `node --check`), Home Assistant's REST API.

**Spec:** `docs/decisions/0014-football.md` (read it first; this plan argues from it). Home Assistant's side has its own plan, with the user's Home Assistant configuration; the Contract below is word for word the same in both, and this side is built and tested against it with fakes.

## Contract

A match, wherever Home Assistant gives one. `?` marks a key left out when it has nothing to say.

| Key | Value |
| --- | --- |
| `id`, `home_id`, `away_id` | strings |
| `kickoff` | ISO time in UTC |
| `state` | `pre`, `in` or `post` |
| `clock`? | "67'", "HT", "FT", "Postponed": ESPN's own words, for the card only |
| `home`, `away` | ESPN's short names ("Man Utd") |
| `home_name`?, `away_name`? | the full name ("Manchester United"), only where it differs from the short one |
| `home_score`?, `away_score`? | integers, once it has started |
| `league`, `slug` | the competition's name and ESPN's slug |
| `phase`? | `first_half`, `half_time`, `second_half`, `extra_time`, `penalties`, `full_time`, or `off` (postponed, cancelled, abandoned) |
| `winner`? | `home` or `away` |
| `shootout`? | `[home, away]` |
| `extra_time`? | `true` when it ended after extra time |
| `venue`? | `{"name": ..., "city": ...}`, in ask answers only |
| `odds`? | `{"home": 55, "draw": 23, "away": 22, "source": "DraftKings"}`, whole percentages adding up to 100, in ask answers only and only before kick-off |

`sensor.football_teams` attributes: `teams` (each `id`, `name`, `asked`, `stale`? (`true`), `now`?, `next` up to 3, `last` up to 3), `live`, `next_kickoff`, `unknown`, `stale`, `trimmed`?, `error`?, and the card's `soon` and `rows`, unchanged.

`shell_command.football_ask` takes `what`, `name`, `date` (`YYYYMMDD`, today if empty) and `days` (1 if empty, 31 at most), and returns `{"stdout": <the JSON below>, "stderr": "", "returncode": 0}`. Every answer has `stale`; `error` when the run failed; `unknown: [name]` when ESPN found nothing by that name.

| `what` | Answer |
| --- | --- |
| `team` | `team` (`id`, `name`, `full_name`?, `followed`), `now`?, `next` up to 5, `last` up to 5, `tables` (each `league`, `group`, `rank`, `of`, `played`, `won`, `drawn`, `lost`, `gd`, `points`) |
| `competition` | `competition` (`slug`, `name`, `round`?), `from`, `days`, `matches`, `match_days` (the `YYYYMMDD` days in the window with a match), `trimmed`? |
| `table` | `competition` (`slug`, `name`), `groups` (each `name` and `rows`: `rank`, `team`, `team_name`?, `played`, `won`, `drawn`, `lost`, `gd`, `points`) |
| `left` | `competition` (`slug`, `name`, `round`?), `knockout` (false for a competition or round nobody is knocked out of), `teams`? (full names), `matches`?, `from_round`? (set when the current round isn't drawn yet and the teams are the winners of this earlier round) |
